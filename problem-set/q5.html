🍱 Q5 · 배치 / 확률적 / 미니배치 경사하강

Compare the batch gradient, stochastic gradient and mini-batch gradient descent methods.

📌 질문 해석

“batch / stochastic / mini-batch gradient descent를 비교하라.” 셋을 업데이트당 예제 수라는 한 축으로 꿰고 trade-off를 보이는 게 핵심.

🍱 세 방법의 차이는 단 하나로 정리된다 — 한 번 업데이트할 때 기울기를 몇 개의 예제로 추정하는가. 손실 함수가 보통 모든 예제의 평균으로 정의되므로 진짜 기울기도 예제별 기울기의 평균이다. 그 평균을 몇 개의 표본으로 추정하느냐가 세 방법의 본질적 차이다.

🏛️ Batch Gradient Descent (전체 배치 경사하강)

매 step마다 전체 훈련 데이터셋의 모든 예제로부터 기울기를 계산해 평균을 낸다. 그 평균이 진짜 기울기에 가장 가까우니, 업데이트 방향이 가장 정확하고 수렴도 매끄럽다.

하지만 단점이 치명적이다. 첫째, 한 step에 데이터 전체를 한 번 훑어야 하니 한 epoch에 단 한 번만 갱신된다 — 매우 느리다. 둘째, 모든 예제의 기울기를 메모리에 동시에 올려야 하니 데이터셋이 크면 메모리가 폭증한다. ImageNet처럼 100만 장 규모 데이터로는 사실상 불가능하다.

🎲 Stochastic Gradient Descent (SGD, 확률적 경사하강)

반대 극단이다. 매 step마다 단 하나의 예제로 기울기를 추정하고 곧바로 업데이트한다. 한 epoch에 데이터 개수만큼 자주 업데이트되니 학습이 매우 빠르게 진행된다.

흥미로운 부작용도 있다. 한 예제만으로 추정한 기울기는 진짜 기울기에서 많이 흔들린다(분산이 크다). 이 잡음이 의도치 않은 이점을 준다 — 모델이 얕은 local minima나 saddle point에 갇혀 있을 때, 잡음 덕분에 빠져나올 가능성이 생긴다.

하지만 단점도 분명하다. 기울기 추정 분산이 커서 수렴이 들쭉날쭉하고, 한 번에 하나만 처리하니 GPU의 병렬 처리 능력을 거의 활용하지 못한다. 현대 하드웨어와는 잘 맞지 않는다.

🎯 Mini-batch Gradient Descent (미니배치, 사실상 표준)

위 두 방법의 절충이다. 매 step마다 m개의 예제(보통 32~256개)로 기울기를 평균낸 뒤 업데이트한다. 현대 딥러닝에서 사실상 모든 옵티마이저가 이 방식을 쓴다.

왜 미니배치가 "sweet spot"인지 두 가지 이유가 있다.

1) 통계적 효율 — 기울기 추정의 정확도는 표본 수가 늘수록 좋아지지만, 그 좋아지는 정도는 표본 수의 제곱근에만 비례한다. 즉 표본을 100배 늘려도 정확도는 10배만 좋아진다. 이걸 "수확 체감"이라고 부른다. 따라서 큰 배치로 정확한 기울기를 한 번 구하는 것보다, 작은 배치로 거친 추정을 자주 하는 게 같은 계산량 대비 더 효과적이다.

2) 하드웨어 효율 — GPU는 행렬 연산을 병렬로 처리한다. m개의 예제를 한 번에 행렬 곱셈으로 처리하는 비용은 1개를 처리하는 비용보다 그렇게 크지 않다 (memory bandwidth 한도까지는). 그래서 m=128 같은 적당한 크기로 묶어 처리하면 SGD보다 같은 시간에 훨씬 많은 예제를 소화할 수 있다.

🗳️ 배치 GD는 전 국민 여론조사를 끝낸 뒤 단 한 번 결정을 내리는 것과 같다 — 정확하지만 결정이 너무 늦다. SGD는 길에서 만나는 1명에게 묻고 즉시 결정하는 것이다 — 빠르지만 잡음이 크다. 미니배치는 대표성 있는 표본 200명에게 묻고 결정하는 것 — 충분히 정확하면서도 빠르고 자주 물을 수 있다.

🎁 보너스: 잡음의 정칙화 효과

미니배치 기울기의 잡음에는 의외의 부수 효과가 있다. 너무 큰 배치(예: 8192 이상)로 학습하면 기울기가 매우 정확해지지만, 그 결과 모델이 sharp minimum(좁고 가파른 골짜기 바닥)에 정착하는 경향이 있다. Sharp minimum은 훈련 데이터에는 잘 맞지만 새 데이터에서 무너지기 쉽다.

반면 적당한 크기 미니배치의 잡음은 모델을 flat minimum(넓고 완만한 골짜기 바닥) 쪽으로 유도한다. Flat minimum은 작은 변동에도 손실이 안정적이라 새 데이터에 더 잘 일반화된다. 즉 미니배치 잡음 자체가 약한 정칙화 역할을 한다 — 너무 크게 잡으면 오히려 일반화 성능이 떨어지는 이유다.

📌 What the question asks

“Compare batch / stochastic / mini-batch gradient descent” — thread them along one axis (examples per update) and show the trade-off.

🍱 The only difference: how many examples estimate the gradient per update. Since the cost is an average over examples, so is the true gradient — it is a question of how many to estimate it from.

🏛️ Batch (full) GD

  • Whole training set per update.
  • Most accurate, smooth convergence.
  • One update per epoch → slow, memory-heavy, impractical at scale 😮‍💨.

🎲 Stochastic GD (1)

  • One example per update.
  • Frequent updates; noise helps escape shallow minima / saddles.
  • High variance, no GPU vectorization, jittery 📈📉.

🎯 Mini-batch GD ($m\approx32$–256) is the standard sweet spot for two reasons.

📊 ① Statistical efficiency: the estimate's standard error scales as $1/\sqrt{m}$ — diminishing returns favor small-ish batches. ⚡ ② Hardware efficiency: the GPU processes the whole batch in parallel.

🗳️ Batch = poll the whole nation, then decide once. SGD = ask one passer-by and decide instantly. Mini-batch = ask a representative sample of 200 — accurate enough, yet fast and frequent.

🎁 Bonus: mini-batch noise is a mild regularizer — overly large batches can generalize worse.

🎯 Model Answer (English)

The three differ only in how many examples estimate the gradient per update. Batch (full) gradient descent uses the whole training set: the gradient is exact and convergence smooth, but each update needs a full pass and large memory, which is impractical on large data. Stochastic gradient descent (SGD) uses a single example per update: updates are frequent and the noise helps escape shallow minima and saddle points, but the gradient is high-variance and cannot exploit GPU vectorisation. Mini-batch gradient descent uses m examples (typically 32-256) and is the modern standard, because the estimate's accuracy improves only as the square root of the batch size — diminishing returns favour small-ish batches — and GPUs process the whole batch in parallel; its residual noise even acts as a mild regulariser by steering training toward flat minima that generalise better.

📝 시험 답안 골격

  • 차이는 업데이트당 예제 수: 전체 / 1개 / m개.
  • 배치=정확하나 느리고 메모리↑, SGD=잦고 잡음 탈출 도움이나 분산↑·벡터화 불가, 미니배치=절충.
  • 미니배치가 표준인 이유 — 표본 늘려도 정확도는 제곱근으로만 좋아짐 (수확 체감) + GPU 병렬효율 + 잡음의 약한 정칙화 (flat minimum 선호).

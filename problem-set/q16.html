🎰 Q16 · 그리드 탐색과 무작위 탐색

In hyperparameter search, what is grid search and random search?

📌 질문 해석

“hyperparameter search에서 grid search와 random search란?” 각 정의 + 왜 random이 종종 이기는지가 핵심 포인트.

🎰 신경망에는 두 종류의 파라미터가 있다. 첫째는 가중치(weight) — 학습 데이터로 gradient descent를 통해 자동 조정된다. 둘째는 hyperparameter — learning rate, layer 수, batch size, 정칙화 계수, dropout 비율 같은 값들이다.

Hyperparameter는 gradient descent로 학습되지 않는다. 그래서 사람이 사전에 정해두거나, 여러 값을 직접 시도해보고 가장 좋은 걸 골라야 한다. 후자를 hyperparameter search라고 부르고, 두 가지 기본 전략이 있다 — grid search와 random search.

🔲 Grid Search (격자 탐색)

각 hyperparameter마다 후보 값들을 미리 정한 뒤, 그 후보들의 모든 조합을 빠짐없이 시도한다.

예를 들어 learning rate는 [0.001, 0.01, 0.1] 세 값을, 정칙화 계수는 [0.0001, 0.001, 0.01] 세 값을 고려한다면, 두 hyperparameter의 모든 조합은 3 × 3 = 9가지다. Grid search는 이 9개 조합을 전부 시도한다.

장점은 단순함과 체계성이다. 단점은 차원의 저주(curse of dimensionality)다. Hyperparameter가 늘어날 때마다 시도 횟수가 지수적으로 폭증한다. 5개 hyperparameter 각각에 후보 5개씩이면 5^5 = 3,125번을 시도해야 한다. 6개로 늘면 15,625번. 현실에서는 한 번 학습에 몇 시간씩 걸리니, 이 비용은 빠르게 감당 불가능해진다.

🎲 Random Search (무작위 탐색)

각 hyperparameter에 대해 후보 분포를 정한 뒤, 그 분포에서 무작위로 N번 추출해 그만큼 시도한다. 후보를 미리 격자로 짜지 않고, 매번 새로운 무작위 조합을 시도한다.

예를 들어 learning rate는 로그 균등 분포 [0.0001, 0.1]에서, 정칙화 계수는 로그 균등 [0.00001, 0.01]에서 추출하기로 정한 뒤, 9번을 무작위로 뽑아 9번 시도한다.

장점이 여럿이다. 첫째, 연속 범위를 자연스럽게 다룬다 (grid는 후보를 미리 정해야 한다). 둘째, 예산을 자유롭게 늘리거나 줄일 수 있다 — grid는 추가 시도가 곧 차원 축의 해상도를 바꿔야 하지만, random은 그냥 한 번 더 뽑으면 끝이다. 셋째, 시도 간 독립이 보장되니 병렬화가 자연스럽다. 그리고 의외로 같은 예산에서 평균적으로 grid보다 더 좋은 hyperparameter를 찾는다.

🔑 왜 Random이 자주 이기는가

이 부분이 가장 흥미롭고, 시험 답안의 핵심이다. 핵심 관찰은 이것이다 — 실제로는 소수의 hyperparameter만 성능에 큰 영향을 미친다. 예를 들어 learning rate는 매우 중요하지만, 어떤 weight initialization 방식을 쓰느냐는 거의 영향이 없을 수도 있다.

이제 9번의 예산이 있다고 하자.

Grid search (3×3): 9번을 쓰지만 각 hyperparameter 축에서 실제로 시도해본 서로 다른 값은 3개뿐이다. learning rate를 3개 값으로만 훑은 셈이다. 중요한 축의 해상도가 3에 묶인다.

Random search: 같은 9번이지만 두 점이 정확히 같은 learning rate 값을 가질 확률은 거의 0이다. 따라서 9번의 시도에서 9개의 서로 다른 learning rate 값을 시험한다. 중요한 축을 3배 더 촘촘하게 훑는다.

요약하면, grid는 예산을 모든 축에 균등하게 나눠 쓰는데 정작 대부분의 축이 중요하지 않다. Random은 우연히 모든 축에 다 다른 값을 줘서, 중요한 축에 자연스럽게 더 많은 해상도를 쓰는 효과가 난다.

🎯 9개 점으로 다트판의 정중앙을 찾는다고 상상해보자. Grid는 3×3 격자에 점을 놓는다 — 가로축으로도 3개 값, 세로축으로도 3개 값만 시도한다. Random은 무작위로 9개 점을 던진다 — 정중앙이 어디에 있든 어느 한 축이라도 그 근처를 지날 가능성이 높다. 중요한 축이 무엇인지 모를 때 random이 유리한 이유다.

📌 실용적 결론

Hyperparameter 수가 늘어날수록 random search의 우위가 커진다. 그래서 현대 딥러닝 실무에서는 random search가 grid search보다 흔히 쓰인다. 더 발전한 방법으로 Bayesian optimization (이전 시도 결과로 다음 시도를 똑똑하게 고르기) 같은 기법도 있지만, 단순함 대비 효과의 측면에서 random search는 여전히 매우 강력한 기본 전략이다.

위젯 16같은 9회 예산 — 중요한 축을 몇 개의 값으로 훑는가

위쪽 곡선이 “중요한 하이퍼파라미터”의 진짜 성능, 옆 축은 “중요하지 않은 파라미터”다. 그리드(왼쪽)는 중요한 축을 sqrt(N) 개 값만 훑지만, 무작위(오른쪽)는 N개의 서로 다른 값을 훑어 봉우리를 맞힐 확률이 높다.

🧠 더 똑똑한 후속은 Bayesian optimization — 지금까지 결과로 성능 곡면의 surrogate 모델을 세우고 다음 시도값을 영리하게 고른다. 하지만 단순함·병렬성·강건함 덕에 random search가 여전히 강력한 기본값이다 ✅.

🎯 Model Answer (English)

Both search hyperparameters that gradient descent cannot tune. Grid search picks a few candidate values per hyperparameter and tries every combination (the Cartesian product), so the number of trials grows exponentially with the number of hyperparameters. Random search instead samples each hyperparameter from a distribution for a fixed number of trials. Random usually wins because typically only a few hyperparameters matter: a 3-by-3 grid tests only 3 distinct values of each parameter, whereas 9 random trials test 9 distinct values of the important one — exploring it three times more finely for the same budget. Bayesian optimisation is the smarter successor, but random search remains a strong, trivially parallelisable baseline.

📝 시험 답안 골격

  • 그리드 = 후보값들의 모든 조합. 무작위 = 분포에서 N번 추출.
  • 그리드는 차원에 지수 폭발 + 각 축을 적은 값만 시험. 무작위는 각 축을 N개 서로 다른 값으로.
  • 이유 — 소수 파라미터만 중요. 무작위가 중요 축을 더 촘촘히. (베이지안 최적화는 더 똑똑한 후속.)

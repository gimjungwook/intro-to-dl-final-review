🧹 Q19 · 정칙화된 오토인코더(regularized autoencoders)

Why do we need regularized autoencoders and how can we make them?

📌 질문 해석

두 갈래 — ① 왜 regularized autoencoder가 필요한지(항등함수 문제), ② 어떻게 만드는지(sparse·denoising·contractive).

🧹 이 질문은 두 부분으로 나뉜다. 먼저 왜 정칙화가 필요한지를 이해해야 하고, 그 다음 어떻게 만드는지 세 가지 대표 방법을 알아본다.

🚨 왜 필요한가: Identity 함수 문제

Autoencoder의 목적은 입력을 압축했다가 다시 복원하면서 데이터의 의미 있는 구조를 학습하는 것이다. 그런데 모델의 capacity(표현력)가 충분히 크면 한 가지 함정에 빠진다.

특히 은닉 차원이 입력 차원과 같거나 더 큰 경우(overcomplete)를 생각해보자. 이때 autoencoder는 굳이 데이터의 구조를 이해할 필요가 없다 — 그냥 입력을 그대로 출력으로 복사하는 identity 함수를 학습하면 끝이다. 복원 오차는 정확히 0이 된다.

문제는 이렇게 학습된 모델이 아무것도 배우지 않았다는 점이다. 압축된 code에는 입력의 모든 정보가 그대로 보존돼 있을 뿐, 어떤 의미 있는 추상화나 패턴 발견은 일어나지 않았다. 우리가 원하는 건 "복사"가 아니라 "데이터의 의미 있는 구조"인데, 모델은 더 쉬운 길(복사)을 선택해버렸다.

그렇다고 capacity를 작게 하는 방법도 있긴 하다 — 은닉 차원을 입력보다 훨씬 작게(undercomplete) 만들면 모델이 정보를 압축하지 않을 수 없다. 하지만 이 방식은 모델 표현력을 강제로 제한하므로 비선형 manifold 같은 복잡한 구조를 잡기 어렵다.

그래서 더 우아한 해법이 필요하다 — capacity는 크게 유지하되, 복원 외의 추가 목표를 부과해서 모델이 단순 복사로는 만족할 수 없게 만든다. 이게 regularized autoencoder의 핵심 아이디어다.

🛠️ 어떻게 만드는가: 세 가지 대표 방식

추가 목표가 무엇이냐에 따라 세 가지 대표 형태로 나뉜다.

✨ 1. Sparse Autoencoder (희소 오토인코더)

은닉층 활성값에 "대부분의 뉴런은 0이어야 한다"는 벌점을 추가한다. 즉 어떤 입력이든 활성화되는 뉴런은 전체의 일부(예: 5%)만이어야 한다.

이 제약이 의미하는 바는 다음과 같다. 모델은 입력의 모든 정보를 사용해 복원할 수 없게 된다 — 사용 가능한 "활성 뉴런 예산"이 제한되어 있다. 그래서 어떤 입력을 잘 표현할 수 있는 뉴런 몇 개를 선택해야 한다.

결과적으로 각 뉴런은 데이터의 특정 "부분(part)"을 담당하는 detector로 학습된다. 얼굴 이미지라면 한 뉴런이 "왼쪽 눈", 다른 뉴런이 "코", 또 다른 뉴런이 "입"을 담당하는 식이다. 이걸 parts-based representation이라고 부른다. 인간의 시각 인지와도 어느 정도 유사한 표현이 자연스럽게 나타난다.

🌫️ 2. Denoising Autoencoder (DAE, 잡음 제거 오토인코더)

가장 우아한 발상이다. 입력에 일부러 잡음을 더해 손상시킨 뒤, 모델이 깨끗한 원본을 복원하도록 학습시킨다.

예를 들어 이미지의 픽셀 일부를 무작위로 0으로 바꾸거나 가우시안 잡음을 더한다. 모델은 그 손상된 이미지를 받고 원래 깨끗한 이미지를 출력해야 한다.

왜 이게 정칙화 효과를 가지는가. 입력이 손상되어 있으니 단순 복사로는 절대 답을 맞힐 수 없다. 모델은 "이런 손상된 입력이라면 원래는 어떤 모습이었을까?"를 추론해야 하는데, 이를 위해서는 데이터 자체의 분포 — 즉 데이터 manifold — 를 이해해야 한다.

예를 들어 손글씨 숫자 이미지에서 픽셀 몇 개가 손상되었어도 모델이 "이건 숫자 7이다"라고 알아본다는 건, 모델이 "7이 어떻게 생겼는지"라는 추상적 개념을 배웠다는 뜻이다. 결과적으로 DAE는 손상된 입력을 데이터 manifold 위로 끌어당기는 vector field를 학습하게 된다.

🤏 3. Contractive Autoencoder (CAE, 수축 오토인코더)

encoder의 출력이 입력의 작은 변화에 둔감하도록 강제하는 정칙화다. 즉 입력 x가 조금 흔들려도 code h가 거의 변하지 않도록 만든다.

이 정칙화는 모델 학습 자체에 추가 비용(입력 변화에 따른 code 변화량의 크기)을 더해서 달성한다. 모델은 가능한 한 입력의 작은 변화를 무시하도록 학습된다.

왜 이게 의미 있는가. 입력의 무관한 변동(예: 미세한 픽셀 잡음, 조명 변화)에는 둔감해야 하지만, 데이터 manifold 위에서의 변동(예: 얼굴 표정 변화, 자세 변화)에는 민감해야 한다. CAE는 결과적으로 manifold에 수직인 방향(noise)으로는 둔감하고, manifold를 따라가는 방향(tangent)으로는 민감한 표현을 학습한다.

📝 정칙화 없는 autoencoder는 받아쓰기 시험에서 문제지를 그대로 베껴 내는 학생과 같다. 만점이지만 이해는 0이다. 세 가지 정칙화는 각각 다른 시험 규칙을 추가한다 — Sparse AE는 "핵심 단어만 골라 적어라" (모든 걸 받아쓰지 마라), Denoising AE는 "일부 글자가 지워진 문제를 받고 원본을 복원해라" (베낄 수 없으니 내용을 이해해야 한다), Contractive AE는 "문제가 살짝 바뀌어도 같은 답을 내라" (표면적 변화 말고 본질을 잡아라). 모두 베끼기 대신 진짜 이해를 강제한다.

📌 정리

Regularized autoencoder가 필요한 이유는 capacity가 충분한 일반 autoencoder가 identity 함수로 도망가버리기 때문이다. 정칙화는 복원 외의 추가 목표를 부과해 이를 막는다. 대표 방식 셋은 sparse(희소성), denoising(잡음 복원), contractive(입력 변화 둔감성)이며, 각각 데이터의 다른 측면을 강조한다. 모두 capacity를 강제로 줄이지 않으면서도 의미 있는 표현 학습을 유도하는 우아한 해법이다.

📌 What the question asks

Two parts — ① why regularized autoencoders are needed (the identity problem), and ② how to build them (sparse, denoising, contractive).

🧹 Why: with enough capacity (especially overcomplete, hidden ≥ input), an autoencoder can learn the identity function — copying input to output with zero error but learning nothing 📋. Regularization adds an objective beyond reconstruction so a useful representation is learned regardless of capacity ✅.

🛠️ How — by the extra objective:

✨ Sparse AEpenalty $\Omega(h)=\lambda\lVert h\rVert_1$ on hidden activations → most units near 0, parts-based features. 🌫️ Denoising AEcorrupt the input $\tilde x$, reconstruct the clean $x$ → copying is impossible, so it must learn the data manifold (a vector field pointing toward it). 🤏 Contractive AEpenalize the encoder Jacobian norm $\lVert\partial h/\partial x\rVert_F^2$ → insensitive to small input changes, sensitive only along the manifold's tangent.
📝 An unregularized AE is a student who copies the question sheet verbatim — full marks, zero understanding. Sparse / denoising / contractive add rules (“write only key words”, “restore the partly-erased question”, “give the same answer if the question changes slightly”) that force understanding instead of copying.
🎯 Model Answer (English)

Why: an autoencoder with enough capacity — especially an over-complete one whose hidden layer is at least as large as the input — can simply learn the identity function, copying input to output with zero reconstruction error while learning nothing useful. Regularisation imposes an additional objective beyond reconstruction so a useful representation is learned regardless of capacity. How: (1) a sparse autoencoder adds a sparsity penalty on the hidden activations, forcing most units to zero and learning parts-based features; (2) a denoising autoencoder corrupts the input and trains the network to reconstruct the clean version, so copying is impossible and it must learn the data manifold; (3) a contractive autoencoder penalises how much the code changes when the input changes slightly (the Jacobian norm), making the code insensitive to small input changes and sensitive only along the manifold.

📝 시험 답안 골격

  • 필요 이유 — 용량 큰 AE는 항등함수를 외워 복사만 함(배움 0). 복원 외 목표를 부과해야 유용 표현.
  • 희소 — 은닉 활성에 희소성 벌점(parts-based 표현). 잡음제거(DAE) — 손상 입력→깨끗 복원(데이터 manifold 학습).
  • 수축(CAE) — 입력 변화에 따른 code 변화량 벌점으로 입력 잡음에 둔감, manifold 접선 방향만 민감.

    손실 곡면 위에서
    학습은 실제로 어떻게 움직이나

    학습이란 곡면 위를 굴러 내려가는 일이다. 1차로 갈지 2차로 갈지, 한 번에 몇 개를 보고 갈지, 관성을 줄지, 절벽을 만나면 어떡할지 — 8장의 모든 결정이 “이 곡면을 어떻게 안전하고 빠르게 내려가는가”라는 한 물음에 답한다.

    ⛰️ Q4 · 경사하강법 vs 뉴턴법

    Describe and compare the gradient descent method and the Newton method.

    두 방법 모두 비용 $J(\theta)$를 최소화하지만, 곡면에 대해 쓰는 정보의 차수가 다르다. 경사하강은 1차(기울기)만, 뉴턴법은 2차(곡률, 헤시안)까지 쓴다.

    경사하강법(gradient descent)은 현재 지점의 기울기 반대 방향으로 일정 보폭만큼 내려간다.

    $$ \theta \leftarrow \theta - \epsilon\, \nabla_\theta J(\theta) $$

    기울기는 “가장 가파른 내리막 방향”만 알려 줄 뿐 얼마나 멀리 가야 바닥인지는 모른다. 그래서 학습률 $\epsilon$을 사람이 정해야 하고, 곡면이 방향마다 기울기가 크게 다른 병든 조건수(ill-conditioned) 골짜기에서는 가파른 축을 따라 좌우로 튕기며 완만한 축으로는 거의 못 나아가는 지그재그가 생긴다.

    뉴턴법(Newton's method)은 현재 지점에서 비용을 2차(이차) 함수로 근사하고, 그 근사 포물면의 최소점으로 단번에 이동한다.

    $$ \theta \leftarrow \theta - H^{-1}\, \nabla_\theta J(\theta), \qquad H = \nabla^2_\theta J(\theta) $$

    헤시안 $H^{-1}$이 방향마다 곡률로 보폭을 자동 조정하므로, 순수 이차 함수라면 단 한 걸음에 바닥에 도달하고 조건수 문제에 면역이다.

    경사하강은 “안개 속에서 발밑 경사만 보고 한 걸음씩 내려가는 등산객”이다. 방향은 알아도 보폭은 감으로 정한다. 뉴턴법은 “골짜기 전체 지형도를 펼쳐 보고 바닥 좌표로 곧장 점프하는 사람”이다. 단, 지형도(헤시안)를 매번 그리고 뒤집는 비용이 막대하다.

    그래서 딥러닝에서는 뉴턴법을 거의 쓰지 못한다. 이유가 셋이다. ① 비용 — 파라미터가 $n$개면 헤시안은 $n\times n$, 역행렬 계산이 $O(n^3)$이다. $n$이 수백만~수십억인 딥넷에서는 불가능하다. ② 안장점 위험 — 비볼록 곡면의 안장점에서 $H$가 양의 정부호가 아니면 뉴턴 스텝이 오히려 안장점이나 극대점으로 끌려간다. ③ 비볼록성 — 국소 이차 근사가 멀리서는 부정확하다. 실제로는 모멘텀, RMSProp, Adam 같은 곡률을 값싸게 근사하는 1차 방법으로 두 세계의 절충을 취한다.

    위젯 04병든 골짜기 — 경사하강의 지그재그 vs 뉴턴의 한 걸음
    경사하강뉴턴법(1걸음)

    조건수 κ를 키워 골짜기를 찌그러뜨릴수록 경사하강(빨강)은 가파른 축을 좌우로 튕기며 더 많은 걸음을 허비한다. 뉴턴법(파랑)은 곡률을 알기에 κ와 무관하게 늘 한 걸음에 바닥으로 점프한다.

    🎯 Model Answer (English)

    Gradient descent is a first-order method using only the gradient, $\theta \leftarrow \theta - \epsilon\nabla J$. It is cheap ($O(n)$ per step) but blind to curvature, so the learning rate must be tuned by hand and it zig-zags on ill-conditioned surfaces. Newton's method is second-order, $\theta \leftarrow \theta - H^{-1}\nabla J$, where the inverse Hessian rescales each direction by its curvature — reaching the minimum of a pure quadratic in a single step and being immune to ill-conditioning. In deep learning Newton is rarely usable: inverting the $n\times n$ Hessian costs $O(n^3)$ for millions of parameters, it can be attracted to saddle points when $H$ is not positive-definite, and the local quadratic model is inaccurate on non-convex loss surfaces. We therefore use cheap curvature-aware first-order methods such as momentum, RMSProp, and Adam.

    📝 시험 답안 골격

    • 경사하강 = 1차(기울기), 뉴턴 = 2차(헤시안). 식 $\theta-\epsilon\nabla J$ vs $\theta-H^{-1}\nabla J$.
    • 뉴턴은 곡률로 보폭 자동조정 → 조건수 면역, 이차함수는 1걸음. 경사하강은 ill-conditioned에서 지그재그.
    • 딥넷에서 뉴턴 못 쓰는 이유 — $O(n^3)$ 비용, 안장점에서 비양정부호, 비볼록. → 모멘텀/Adam이 절충.

    🍱 Q5 · 배치 / 확률적 / 미니배치 경사하강

    Compare the batch gradient, stochastic gradient and mini-batch gradient descent methods.

    셋의 차이는 단 하나 — 한 번 업데이트할 때 기울기를 몇 개의 예제로 추정하는가다. 비용 함수가 보통 훈련 예제들에 대한 평균이므로, 진짜 기울기도 예제별 기울기의 평균이고, 그 평균을 몇 개로 추정하느냐의 문제로 환원된다.

    배치 (전체) GD

    • 매 업데이트에 전체 훈련 집합의 기울기.
    • 가장 정확한 기울기, 매끄러운 수렴.
    • 한 epoch에 한 번만 갱신 → 느리고, 메모리 폭증, 큰 데이터에 비현실적.

    확률적(SGD, 1개)

    • 매 업데이트에 예제 1개의 기울기.
    • 매우 잦은 갱신, 잡음이 얕은 극소·안장점 탈출을 도움.
    • 기울기 분산이 큼, 벡터화·GPU 활용 불가, 수렴이 들쭉날쭉.

    미니배치(mini-batch) GD는 둘 사이의 절충으로, 매 업데이트에 $m$개(보통 32~256)를 쓴다. 사실상 모든 현대 딥러닝의 표준이며, 두 가지 이유로 “스위트 스폿”이다.

    첫째, 통계적 효율. 기울기 추정의 표준오차는 표본 수의 제곱근에 반비례한다($\propto 1/\sqrt{m}$). 즉 배치를 키워도 정확도는 제곱근으로만 좋아져 수확 체감이 빠르다. 100개로 얻는 정확도를 위해 10,000개를 쓰는 것은 100배 비용에 10배 정확도일 뿐이다. 작은 배치로 거친 추정을 자주 하는 편이 이득이다. 둘째, 하드웨어 효율. GPU는 $m$개를 한 번에 병렬 처리하므로, 1개씩 처리하는 SGD보다 미니배치가 같은 시간에 훨씬 많은 예제를 소화한다.

    전체 배치는 “여론조사에 전 국민을 다 묻고 한 번 결정”, SGD는 “길에서 한 명 붙잡고 묻고 바로 결정”, 미니배치는 “대표 표본 200명에게 묻고 결정”이다. 200명이면 충분히 정확하면서도 빠르고 자주 물을 수 있다.

    덤으로 미니배치의 기울기 잡음은 약한 정칙화 효과를 낸다 — 너무 큰 배치는 정확하지만 일반화가 나빠지는 경향이 보고된다. 작은 배치의 잡음이 평평한 최소점을 선호하게 만들기 때문이다.

    🎯 Model Answer (English)

    The three differ only in how many examples estimate the gradient per update. Batch (full) gradient descent uses the whole training set: the gradient is exact and convergence smooth, but each update needs a full pass and large memory, which is impractical on large data. Stochastic gradient descent (SGD) uses a single example per update: updates are frequent and the noise helps escape shallow minima and saddle points, but the gradient is high-variance and cannot exploit GPU vectorisation. Mini-batch gradient descent uses $m$ examples (typically 32–256) and is the modern standard, because the estimate's standard error scales as $1/\sqrt{m}$ — diminishing returns favour small-ish batches — and GPUs process the whole batch in parallel; its residual noise even acts as a mild regulariser.

    📝 시험 답안 골격

    • 차이는 업데이트당 예제 수: 전체 / 1개 / m개.
    • 배치=정확하나 느리고 메모리↑, SGD=잦고 잡음 탈출 도움이나 분산↑·벡터화 불가, 미니배치=절충.
    • 미니배치가 표준인 이유 — 분산 $\propto 1/\sqrt m$ 수확체감 + GPU 병렬효율 + 잡음의 약한 정칙화.

    🏂 Q6 · 최적화의 모멘텀(momentum)

    What is the momentum in optimization?

    모멘텀은 과거 기울기들의 지수 감쇠 이동평균을 속도(velocity) 변수 $v$에 누적해, 매 스텝이 “지금 기울기”뿐 아니라 “지금까지의 관성”을 함께 따르게 하는 기법이다.

    $$ v \leftarrow \alpha v - \epsilon\, \nabla_\theta J(\theta), \qquad \theta \leftarrow \theta + v $$

    $\alpha\in[0,1)$는 관성 계수(보통 0.9). 과거 속도의 $\alpha$배를 유지하며 새 기울기를 더한다.

    왜 필요한가? 병든 골짜기(Q4)에서 경사하강은 가파른 축을 따라 좌우로 튕긴다. 그런데 이 튕김은 매 스텝 방향이 반대로 뒤집히므로 평균하면 상쇄된다. 반대로 골짜기를 따라 내려가는 완만한 방향은 매 스텝 방향이 일정하므로 누적되어 가속된다. 모멘텀은 바로 이 평균을 취해 진동을 죽이고 일관된 방향에 속도를 붙인다.

    경사하강이 “매 순간 멈춰 서서 방향만 보고 한 걸음 떼는 사람”이라면, 모멘텀은 “언덕을 굴러 내려가는 무거운 공”이다. 공은 잔돌멩이(미니배치 잡음)나 작은 웅덩이(얕은 극소)에 멈추지 않고 관성으로 통과하며, 일관된 내리막에서는 점점 빨라진다.

    모멘텀이 도달하는 종단 속도는 기울기가 일정할 때 $\dfrac{\epsilon \lVert g\rVert}{1-\alpha}$로, $\alpha=0.9$면 보폭이 약 10배로 증폭된다. 미니배치 잡음을 평균해 경로를 매끄럽게 하는 효과도 있다. 변형인 네스테로프 모멘텀은 기울기를 현재 위치가 아니라 관성으로 “미리 가 볼” 위치에서 계산해, 과도하게 지나치기 전에 교정한다.

    🎯 Model Answer (English)

    Momentum accumulates an exponentially decaying moving average of past gradients into a velocity term: $v \leftarrow \alpha v - \epsilon\nabla J$, then $\theta \leftarrow \theta + v$. It helps because in an ill-conditioned ravine the oscillating directions reverse every step and cancel out on average, while the consistent downhill direction accumulates and accelerates — like a heavy ball rolling that coasts through small bumps (mini-batch noise) and shallow dips (poor local minima). With $\alpha = 0.9$ the effective step is amplified about tenfold (terminal velocity $\epsilon\lVert g\rVert/(1-\alpha)$). Nesterov momentum refines this by evaluating the gradient at the look-ahead position, correcting before it overshoots.

    📝 시험 답안 골격

    • 정의 — 과거 기울기의 지수평균을 속도 $v$에 누적: $v\leftarrow\alpha v-\epsilon\nabla J,\ \theta\leftarrow\theta+v$.
    • 효과 — 진동 축은 상쇄, 일관된 축은 누적·가속. 잡음·얕은 극소 통과. 종단속도 $\epsilon\|g\|/(1-\alpha)$.
    • 네스테로프 = 미리 가본 위치에서 기울기 계산.

    🧗 Q7 · 절벽(cliffs)과 기울기 폭발(exploding gradient)

    As an optimization challenge, what is the relation between cliffs and exploding gradient?

    깊은 네트워크나 RNN의 손실 곡면에는 절벽(cliff)이 흔하다 — 평평하던 지형이 갑자기 거의 수직으로 떨어지는 영역이다. 이런 절벽은 여러 층(또는 여러 시간 스텝)에 걸쳐 가중치가 반복적으로 곱해지기 때문에 생긴다. 비슷한 큰 가중치를 여러 번 곱하면 출력과 그 기울기가 지수적으로 커지는 구간이 만들어진다.

    둘의 관계는 원인과 증상으로 보면 명확하다. 절벽은 기하학적 원인이고, 기울기 폭발은 그 절벽 가장자리에서 나타나는 증상이다. 절벽 근처에서 기울기의 크기는 폭발적으로 커진다. 보통의 학습률로 그 거대한 기울기에 보폭을 곱하면, 파라미터가 한 번에 아주 먼 곳으로 날아가 버려 그동안의 학습을 통째로 망친다.

    절벽 가장자리에 선 등산객을 떠올리자. 발밑 경사(기울기)가 절벽이라 무한대에 가깝다. 평소처럼 “경사 × 보폭”으로 한 걸음을 떼면 절벽 아래 수 킬로미터 밖으로 내던져진다. 절벽이라는 지형(원인)이 거대한 한 걸음(폭발이라는 증상)을 낳는 것이다.

    RNN에서 이 현상은 시간축에서 두드러진다. 역전파가 시간을 거슬러 가며 순환 가중치 행렬을 반복 곱하는데, 그 최대 고윳값이 1보다 크면 기울기가 시간 스텝 수에 따라 지수적으로 커진다 — 바로 기울기 폭발이고, 손실 곡면에는 그에 대응하는 절벽이 생긴다(반대로 1보다 작으면 기울기 소실, Q13).

    처방은 기울기 클리핑(Q15)이다. 방향은 그대로 두되 보폭의 크기만 상한으로 잘라, 절벽을 만나도 멀리 내던져지지 않고 가장자리를 따라 조심스럽게 내려가게 한다.

    🎯 Model Answer (English)

    Cliffs are regions of the loss surface that drop almost vertically; they arise in deep networks and RNNs because weights are multiplied repeatedly across layers or time steps. The relation is one of cause and symptom: the cliff is the geometric cause, and the exploding gradient is the symptom at its edge. Near a cliff the gradient magnitude blows up, so a normal-sized step hurls the parameters far away and destroys prior progress. In RNNs this occurs when the recurrent weight matrix's largest eigenvalue exceeds 1, making the gradient grow exponentially with the number of time steps. The standard remedy is gradient clipping (Q15), which caps the step size while keeping its direction.

    📝 시험 답안 골격

    • 절벽 = 가중치 반복 곱으로 생긴 거의 수직인 손실 영역(기하학적 원인).
    • 기울기 폭발 = 절벽 근처에서 기울기 크기가 폭증하는 증상. 보폭 곱하면 파라미터가 멀리 날아감.
    • RNN에서는 순환행렬 최대고윳값 >1 → 시간에 지수적 폭발. 처방 = 기울기 클리핑(Q15).

    🔀 Q8 · 가중치 공간 대칭성(weight space symmetry)

    What is the weight space symmetry?

    가중치 공간 대칭성이란, 서로 다른 가중치 설정이 정확히 같은 입출력 함수를 구현하는 현상이다. 신경망은 “비식별(non-identifiable)” 모델이다 — 함수를 보고 가중치를 유일하게 거꾸로 알아낼 수 없다.

    가장 흔한 예가 은닉 유닛 교환 대칭이다. 한 은닉층에 $m$개의 유닛이 있을 때, 두 유닛의 들어오는 가중치와 나가는 가중치를 함께 맞바꾸면 네트워크가 계산하는 함수는 전혀 변하지 않는다. 유닛은 단지 이름표만 바뀐 셈이다. $m$개 유닛을 재배열하는 방법은 $m!$가지이므로, 같은 함수를 주는 동등한 가중치 설정이 최소 $m!$개 존재한다.

    오케스트라에서 제1바이올린 주자와 제2바이올린 주자가 자리를 맞바꿔도 똑같은 악보를 똑같이 연주하면 청중이 듣는 소리는 동일하다. 연주자(유닛)의 자리 배치는 $m!$가지지만 음악(함수)은 하나다. 가중치를 보고 “누가 어디 앉았는지”는 알 수 없다.

    $\tanh$처럼 홀함수인 활성함수에서는 한 유닛의 들어오고 나가는 가중치 부호를 모두 뒤집어도 함수가 같은 부호 반전 대칭도 추가된다. 이런 대칭들이 곱해져 한 네트워크가 표현하는 함수마다 엄청나게 많은 동등 가중치 설정이 딸려 온다.

    함의는 셋이다. ① 비용 함수의 전역 최소점이 최소 $m!$개 존재한다(모두 동등하므로 어느 것에 도달하든 무방하다). ② 곡면이 비볼록이 되는 한 원인이다. ③ 개별 가중치 값 자체에는 절대적 의미가 없다 — 가중치를 직접 해석하려는 시도가 위험한 이유다. 다만 모든 사본이 동등하므로 이 대칭 자체가 최적화를 특별히 어렵게 만들지는 않는다.

    🎯 Model Answer (English)

    Weight-space symmetry is the fact that many different weight settings implement exactly the same input–output function, so the network is non-identifiable — you cannot recover unique weights from the function. The most common case is hidden-unit permutation: swapping the incoming and outgoing weights of two hidden units leaves the computed function unchanged, so $m$ units yield at least $m!$ equivalent configurations; odd activations such as $\tanh$ add a sign-flip symmetry. The consequences are that the loss has at least $m!$ equivalent global minima, that this is one source of non-convexity, and that an individual weight value has no absolute meaning — but since all copies are equivalent, the symmetry itself does not make optimisation harder.

    📝 시험 답안 골격

    • 정의 — 다른 가중치가 같은 함수를 구현(비식별 모델).
    • 은닉 유닛 $m$개 재배열 → $m!$개 동등 설정. tanh는 부호반전 대칭 추가.
    • 함의 — 동등 전역최소 $m!$개, 비볼록성 한 원인, 개별 가중치 해석 불가.

    ✂️ Q15 · 기울기 클리핑(gradient clipping)

    What is gradient clipping?

    기울기 클리핑은 기울기의 크기가 임계값을 넘으면 방향은 보존한 채 크기만 임계값으로 줄이는 기법이다. 가장 흔한 노름 클리핑은 다음과 같다.

    $$ \text{if } \lVert g\rVert > \tau:\quad g \leftarrow \tau\,\frac{g}{\lVert g\rVert} $$

    기울기 벡터를 임계값 $\tau$ 길이로 정규화. 방향은 그대로, 길이만 상한.

    이것은 Q7의 절벽/기울기 폭발에 대한 직접 처방이다. 절벽 근처에서 기울기가 폭발하면 한 걸음에 파라미터가 멀리 날아가는데, 클리핑은 그 한 걸음의 보폭을 안전한 상한으로 묶는다. 핵심은 방향을 바꾸지 않는다는 점이다 — 여전히 내리막 방향으로 가되, 절벽 아래로 내던져지지 않을 만큼만 간다.

    클리핑은 자동차의 속도 제한 장치와 같다. 운전자가 가속 페달(기울기)을 아무리 세게 밟아도 시속 100km를 넘지 않게 막는다. 가려는 방향(핸들)은 그대로 두고 속도만 잘라, 급경사에서 차가 통제를 벗어나 날아가는 일을 막는다.

    RNN 학습의 사실상 표준 안전장치다. 요소별로 $[-v, v]$에 자르는 방식도 있으나, 노름 클리핑이 방향을 보존하므로 더 선호된다.

    🎯 Model Answer (English)

    Gradient clipping rescales the gradient whenever its norm exceeds a threshold $\tau$, while preserving its direction: if $\lVert g\rVert > \tau$ then $g \leftarrow \tau\,g/\lVert g\rVert$. It is the direct remedy for cliffs and exploding gradients (Q7): when the gradient blows up near a cliff, clipping caps the step so the parameters are not catapulted away, yet the descent direction is unchanged — like a car's speed limiter that bounds how fast you go without changing where you steer. It is a standard safeguard in RNN training; an element-wise variant clipping each component to $[-v, v]$ exists, but norm clipping is preferred because it keeps the direction intact.

    📝 시험 답안 골격

    • 정의 — $\lVert g\rVert>\tau$면 $g\leftarrow\tau g/\lVert g\rVert$. 방향 보존, 크기만 상한.
    • 목적 — 절벽/기울기 폭발(Q7) 처방. 한 걸음이 파라미터를 멀리 날리는 것을 방지.
    • RNN 표준. 방향 보존이 핵심.

    🎰 Q16 · 그리드 탐색과 무작위 탐색

    In hyperparameter search, what is grid search and random search?

    하이퍼파라미터(학습률, 층 수, 정칙화 계수 등)는 경사하강으로 학습되지 않으므로 바깥에서 탐색해야 한다. 두 가지 기본 전략이 있다.

    그리드 탐색 (grid search)

    • 각 하이퍼파라미터마다 후보 값 몇 개를 정해 모든 조합(데카르트 곱)을 시도.
    • 예: 학습률 3값 × 정칙화 3값 = 9회.
    • 하이퍼파라미터 수에 따라 시도 횟수가 지수적으로 폭발(차원의 저주).

    무작위 탐색 (random search)

    • 각 하이퍼파라미터를 분포에서 무작위로 추출해 정해진 횟수만큼 시도.
    • 연속 범위를 자연스럽게 다루고, 시도 추가·병렬화가 쉽다.
    • 같은 예산에서 보통 그리드보다 더 좋은 값을 찾는다.

    왜 무작위가 그리드를 이기는가? 핵심 관찰은 “대개 소수의 하이퍼파라미터만 성능에 크게 영향을 준다”는 것이다. 3×3 그리드는 9번을 쓰지만 각 파라미터의 서로 다른 값은 단 3개만 시험한다 — 중요한 파라미터의 해상도가 3에 묶인다. 같은 9번을 무작위로 쓰면 두 점이 같은 좌표를 공유할 일이 거의 없어 각 파라미터마다 9개의 서로 다른 값을 시험한다. 중요한 축을 3배 더 촘촘히 훑는 셈이다. 그리드는 “중요하지 않은 파라미터의 여러 값”에 시도를 낭비하지만, 무작위는 그 낭비가 없다.

    위젯 16같은 9회 예산 — 중요한 축을 몇 개의 값으로 훑는가

    위쪽 곡선이 “중요한 하이퍼파라미터”의 진짜 성능, 옆 축은 “중요하지 않은 파라미터”다. 그리드(왼쪽)는 중요한 축을 $\sqrt N$개 값만 훑지만, 무작위(오른쪽)는 N개의 서로 다른 값을 훑어 봉우리를 맞힐 확률이 높다.

    더 똑똑한 후속 기법은 베이지안 최적화로, 지금까지의 결과로 성능 곡면의 대리 모델을 세우고 다음에 시도할 값을 똑똑하게 고른다. 하지만 단순함, 병렬성, 강건함 때문에 무작위 탐색이 여전히 강력한 기본값이다.

    🎯 Model Answer (English)

    Both search hyperparameters that gradient descent cannot tune. Grid search picks a few candidate values per hyperparameter and tries every combination (the Cartesian product), so the number of trials grows exponentially with the number of hyperparameters. Random search instead samples each hyperparameter from a distribution for a fixed number of trials. Random usually wins because typically only a few hyperparameters matter: a $3\times3$ grid tests only 3 distinct values of each parameter, whereas 9 random trials test 9 distinct values of the important one — exploring it three times more finely for the same budget. Bayesian optimisation is the smarter successor, but random search remains a strong, trivially parallelisable baseline.

    📝 시험 답안 골격

    • 그리드 = 후보값들의 모든 조합. 무작위 = 분포에서 N번 추출.
    • 그리드는 차원에 지수 폭발 + 각 축을 적은 값만 시험. 무작위는 각 축을 N개 서로 다른 값으로.
    • 이유 — 소수 파라미터만 중요. 무작위가 중요 축을 더 촘촘히. (베이지안 최적화는 더 똑똑한 후속.)

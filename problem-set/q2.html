🔗 Q2 · 파라미터 묶기(tying)와 파라미터 공유(sharing)

Explain the parameter tying and parameter sharing.

📌 질문 해석

“parameter tying과 parameter sharing을 설명하라.” 두 용어의 정의 + 둘의 차이(강제의 세기) + 대표 예시(CNN/RNN)를 함께 보여야 한다.

🔗 Parameter tying과 parameter sharing 모두 "어떤 파라미터들이 서로 관련 있다"는 사전 지식(prior)을 모델에 박아 넣는 방법이다. 두 방법의 차이는 그 관련성을 얼마나 강하게 강제하느냐에 있다.

🪢 Parameter Tying (묶기) — "비슷해야 한다"

Tying은 두 파라미터 집합이 가깝게 유지되도록 부드럽게 유도하는 방법이다. 두 집합은 여전히 별개로 존재하며 각자 자기 값을 갖지만, 학습 중에 "둘이 너무 멀어지면 손실에 벌점"이 추가된다.

예를 들어 같은 데이터로 두 모델을 학습시키는 상황을 생각해보자. 하나는 지도 학습 모델(레이블이 있는 데이터로), 다른 하나는 비지도 학습 모델(레이블 없이)이다. 두 모델이 같은 입력을 다루니까 내부 표현이 비슷해야 한다는 가정이 자연스럽다. 이때 tying을 쓰면 두 모델의 가중치가 완전히 똑같지는 않더라도 서로 너무 다르지 않게 유지된다. 한 모델이 발견한 패턴이 다른 모델로 자연스럽게 흘러간다.

도메인 적응(domain adaptation)도 같은 원리다. 영어 텍스트로 학습한 모델과 한국어 텍스트로 학습한 모델이 있을 때, 두 모델의 일부 layer를 tying으로 묶어두면 언어가 달라도 공통 표현(예: 단어의 의미 구조)이 비슷하게 유지된다.

핵심: 두 파라미터 집합이 가깝지만 다를 수 있는 자유를 준다. 두 task가 비슷하긴 하지만 완전히 똑같진 않은 상황에 적합하다.

🔒 Parameter Sharing (공유) — "정확히 같아야 한다"

Sharing은 한 단계 더 강한 제약이다. 여러 위치의 파라미터를 완전히 동일하게 강제한다 — 메모리상으로도 같은 값을 가리킨다. 벌점이 아니라 절대 위반 불가능한 hard constraint다.

대표 예는 CNN의 합성곱 필터다. 3×3 필터 하나가 이미지의 모든 위치를 똑같이 훑는다. 왼쪽 위에서 쓰는 필터값과 오른쪽 아래에서 쓰는 필터값이 다르지 않다 — 메모리상 같은 값이다. 이게 가능한 이유는 "강아지 패턴은 화면 어디에 있든 강아지"라는 위치 무관성(translation invariance) prior가 옳기 때문이다.

RNN도 마찬가지다. 시간 t=1에서 입력을 처리하는 가중치와 t=100에서 처리하는 가중치를 정확히 같게 묶는다. 시간 어디에서든 "다음 상태 만들기" 규칙이 동일하다는 가정이다.

Sharing의 이점은 두 가지다. 첫째, 메모리 절감. 28×28 이미지를 100차원으로 매핑할 때 fully-connected라면 약 7만 8천 개의 가중치가 필요하지만, 3×3 합성곱 100채널이라면 단 900개로 끝난다. 둘째, 등가성(equivariance) 보너스. 입력 이미지를 옆으로 옮기면 출력도 똑같이 옆으로 옮겨진다 — 위치 정보가 자연스럽게 보존된다.

✨ 두 방법의 핵심 관계

Sharing은 tying의 극단이다. Tying에서 "둘이 멀어지면 벌점"의 강도를 무한대로 키우면, 차이는 0이 되어야만 한다 — 즉 둘이 완전히 같아져야 한다. 그게 sharing이다.

그래서 두 방법은 같은 스펙트럼 위에 있다. Tying은 약한 prior("비슷해야 해"), sharing은 무한히 강한 prior("같아야 해").

🎓 비유로 보면, tying은 두 학생을 같은 조에 묶어 답이 비슷해지도록 유도하는 것과 같다 — 각자 답안지를 따로 내지만 의견을 교환했으니 답이 닮아간다. Sharing은 두 학생이 답안지 한 장을 함께 쓰는 것과 같다 — 물리적으로 같은 답이 강제되고, 채점할 답안지도 단 한 장이다.

🛠️ 실무 선택 기준

실무에서는 sharing이 훨씬 흔하다. CNN과 RNN, 그리고 그 변형들(Transformer의 multi-head attention에서도 weight를 head 간 공유하는 변형이 있다) 모두 sharing을 핵심 도구로 쓴다. 이유는 (가) 메모리 절감 효과가 크고, (나) "같은 패턴이 어디 있든 같다"라는 가정이 이미지·시퀀스·텍스트에 잘 맞기 때문이다.

반면 tying은 "완전히 같지는 않지만 관련 있다"를 표현해야 할 때 쓴다. 멀티태스크 학습에서 task별 head는 다르되 공통 layer는 가깝게 유지하고 싶을 때, 또는 한 모델의 인코더와 디코더가 비슷한 표현을 다루도록 부드럽게 묶고 싶을 때 적합하다.

📌 What the question asks

“Explain parameter tying and parameter sharing” — give each definition, the difference (how hard the constraint is), and an example.

🔗 Both encode the prior that some parameters are related. The difference is the strength of the constraint 💪.

🪢 Parameter Tying

  • Softly penalize two sets to be close: $\Omega(w_A,w_B)=\lVert w_A-w_B\rVert_2^2$.
  • Parameters stay separate but are pulled together.
  • e.g. a supervised model ↔ unsupervised model on the same input; domain adaptation.

🔒 Parameter Sharing

  • Force parameters to be exactly equal — the same memory.
  • A hard constraint, not a penalty.
  • e.g. CNN kernels (across space), RNN weights (across time).

✨ Key relation: sharing is the limit of tying with an infinite penalty (the distance is forced to 0) 🟰. So tying = “should be similar” (weak prior), sharing = “must be equal” (infinitely strong prior).

🎓 Tying = putting two students in one group so their answers resemble each other (separate answer sheets). Sharing = the two writing on a single shared sheet — identical answers are forced, and there is one sheet to grade.

🛠️ Sharing is more common: it saves memory and matches the “same pattern anywhere” assumption of images/sequences, and it grants translation equivariance for free. Tying fits when two models should be related but not identical.

🎯 Model Answer (English)

Both encode the prior that certain parameters are related; they differ in how hard that constraint is. Parameter tying adds a soft penalty on the distance between two parameter sets that pulls them close together (each set still kept separate), used when two related models or tasks should resemble each other. Parameter sharing forces parameters to be exactly identical — they are literally the same memory — as in CNN kernels reused across spatial positions or RNN weights reused across time steps. Sharing is the limiting case of tying with an infinite penalty, so it acts as an infinitely strong prior; it additionally saves memory and grants translation equivariance for free.

🇰🇷 모범답안 (한국어)

둘 다 '어떤 파라미터들은 서로 관련 있다'는 사전을 거는 방법이지만, 제약의 강도가 다르다. 파라미터 묶기(tying)는 두 파라미터 집합의 거리에 부드러운 벌점을 더해 서로 가깝게 당기되 각자 별개로 유지하며, 관련된 두 모델이나 과제가 비슷해야 할 때 쓴다. 파라미터 공유(sharing)는 파라미터를 정확히 동일하게(물리적으로 같은 메모리) 강제하며, CNN 커널을 모든 공간 위치에 재사용하거나 RNN 가중치를 모든 시간 단계에 재사용하는 것이 예다. 공유는 거리 벌점을 무한대로 키운 묶기의 극한이라 무한히 강한 사전으로 작동하며, 추가로 메모리를 절감하고 평행이동 등가성(equivariance)을 공짜로 준다.

📝 시험 답안 골격

  • 묶기 = 부드러운 벌점으로 두 파라미터를 가깝게. 공유 = 정확히 같은 파라미터(하드 제약, 같은 메모리).
  • 공유는 묶기의 극단(거리 벌점 무한대) = 무한히 강한 사전.
  • 공유 예 CNN·RNN, 묶기 예 지도/비지도 결합·도메인 적응. 공유는 메모리 절감 + 등가성 보너스.
